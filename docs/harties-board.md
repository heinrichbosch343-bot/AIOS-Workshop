# System: Harties Board

> A promotion board for the Hartbeespoort area, built as a website that works like an app: dated promo cards by category and by day, one-tap WhatsApp, and an "Add to my phone" button.

## Architecture

```
PecanHood Hyper WhatsApp export (context/group/chat.txt from 30 Oct, or the 22 Oct zip in context/import; both gitignored)
   --> scripts/harties_seed.py --> outputs/community-app/seed/candidates.json (gitignored)
   --> hand review --> seed.local.json (gitignored)
   --> scripts/harties_posts.py + enrich.json (hand picks: which message each page quotes,
       contact details, picture paths) --> seed.local.json, copied into the app's data/
   --> Harties Board (Next.js 16, C:/Users/gamin/BoschAI/harties-board, port 3200)
         Today / Browse / Saved / Post, passcode gate, flyer reading with Claude
```

The app lives **outside** this public repo, in its own private git with no remote, because its seed holds real local businesses from a private group, and because Next.js builds fail on long Windows paths.

## How It Works

1. A neighbour taps the link. Browsing needs no account; a slim bar under the Today picture has an "Add to phone" button (Chrome's own install box on Android in one tap; every other phone opens `/install`, with an iPhone / Android switch and the steps, iPhone steps 2 to 4 as real screenshots).
2. Every promo has a schedule (once, a date range, or weekly), so the app lists it on each day it is on, ordered fairly (time first, daily shuffle for ties, at most two cards per business).
3. The main button opens WhatsApp with "Hi, I saw ... on Harties Board", but only for numbers that can receive WhatsApp (06x, 07x, 081-084); others get Call.
4. A business snaps its flyer; Claude reads it into a fixed JSON shape, the server re-checks every field, and the owner confirms in a form. In Stage A nothing is saved.
5. The admin's `/digest` page makes one "Today in Harties" message to paste into the group.
6. Every picture shows whole, in its own shape (its size is read from the file; a picture outside the limits sits on a blurred copy of itself), and a tap opens it full screen. The look is black, green and white with a faint grain.
7. Business and promo pages show "What they posted" (the advertiser's own message from the group, with its date, folded when long) and a contact list (call, email, website, Instagram, Facebook, address). A business page also has a **"More pictures" gallery** (`components/Gallery.tsx`): the business's own pictures from the group in two columns, each whole; a tap opens them full screen to swipe through (a native dialog, scroll-snap, counter, arrow keys, Escape). The main picture of a listing is its own advert's picture from the group when it has one, else (35 listings, from the first week) a picture from its website or Google Maps listing; `data/media-sources.local.json` in the app records those.

## Common Operations

**Rebuild the seed candidates:**
```bash
uv run --no-project --python 3.12 python -I -X utf8 scripts/harties_seed.py
```

**Copy the picked posts, contacts and pictures into the seed (after editing `enrich.json`):**
```bash
uv run --no-project --python 3.12 python -I -X utf8 scripts/harties_posts.py --dry   # report only
uv run --no-project --python 3.12 python -I -X utf8 scripts/harties_posts.py         # write + copy into the app
```

**Put the group's own pictures on the listings (needs an export made WITH media: iPhone Export Chat, Attach Media; Android Export chat, Include media):** `python3 scripts/harties_media.py "PecanHood Hyper.zip" --dry` reads the chat, finds the picture that came with each pick's advert (the newest advert that has one; a caption and its flyer sent as two messages are joined; anything under 240 px is skipped), and writes contact sheets to `outputs/community-app/seed/media-review/`. Look at every sheet first (no residents, children, house numbers or street maps). Then run it without `--dry` (add `--replace` to let group pictures win over pictures from websites): it writes `<name>.jpg` (1600 long side) and `<name>-sm.jpg` (800 wide) into the app's `public/media`, sets `image` in `enrich.json` (backup kept), and `harties_posts.py --app` copies the paths into the seed. On 2 Nov the exports had no media: 73 of the 87 listings with no picture had posted one.

**Publish to Railway (live at https://hartisboard.up.railway.app, 2 Nov). The site must never go down, so only these two commands change the live service:** commit on `main` in the app folder, then `npm run ship` (first runs types, tests and a production build on that commit, then builds the `live` branch = main + real seed + pictures and pushes it), then `python3 scripts/hartisboard_deploy.py` (checks the site is up, deploys the newest `live` commit, requires the real address to answer 200, and rolls back to the last working version by itself if it does not; `--rollback` does that by hand). See "Safe changes" below. Railway has no push trigger on this service, because the token is a project token and cannot make one; connecting the service to the `live` branch in the dashboard (Settings, Source) would make pushes deploy alone. The service sits in the Railway project that used to be the Halloween RSVP (project id in the script), next to the old `pecanwood-halloween` service, which was left alone. Variables: `DEMO_PASSCODE` (the passcode people type), `NEXT_PUBLIC_SITE_URL`, `TRUSTED_HOPS=2`. The repo is private.

**Add what is new in a later export:** put the export at `context/group/chat.txt` (the scripts read it by default; `--zip` takes a zip or a txt), list the messages newer than the last export, read them, and add new businesses and promos to the `new` section of `enrich.json` (rows in the seed's own shape, with their post picks under `posts`). `harties_posts.py --dry` reports `new`, `keep` (already there) or `MISS` (for example a number not printed in any advert), and the real run writes the seed and copies it into the app.

**Read every advertiser again (after a new export):** run `scripts/harties_seed.py --min-posts 1 --events-since <date>` (back up `candidates.json` first, it is overwritten), group each advertiser's own adverts into batches, and have drafters follow a written brief (who goes on, row formats, categories, never invent a fact, numbers only from their own adverts). Then merge with the app's own `parseBoard`, check every number against that advertiser's adverts, drop duplicates by name, read every skip reason, and add each new page's post pick to `enrich.json`. The 26 Oct scripts (bundle, merge, fix, pictures) lived in the session scratchpad; the brief's rules are in the plan's Implementation Notes.

**Give every business a gallery of its group pictures (needs an export made WITH media; built 2 Nov 2026 from the 1.3 GB zip, 5,849 pictures):** (1) `python3 scripts/harties_media.py "<zip>" --dry` and look at the sheets, then without `--dry` (add `--skip business:x promo:y` for any picture with faces or someone else's post): it fills listings that have no picture from their own advert. (2) `python3 scripts/harties_gallery.py collect "<zip>"` cuts `outputs/community-app/seed/gallery/<slug>/sheet-N.jpg` (20 numbered pictures a sheet, newest first, at most 80 a business) and `batches.json`. (3) Reviewers (Sonnet agents, one batch each, 240 pictures) write `gallery/verdicts/<slug>.json` with keep / score / kind / concerns; they judge relevance (a sender also posts second-hand goods and other people's adverts, so most pictures of a business's sender are NOT its own), people, privacy, quality and repeats. (4) `python3 scripts/harties_gallery.py apply "<zip>"` writes the pictures and the picks; **then look yourself at every picture the reviewers flagged** (a sheet of those is built from `applied.json`) and a second reviewer pass on the rest for dated flyers and misses; removals go into `gallery/manual-drops.json`, then apply again (safe to repeat). (5) `python3 scripts/harties_posts.py` (it copies to the app by default; `--app` takes a path, not a flag) and `npm run ship` + `hartisboard_deploy.py` in the app.
**Rules the reviews applied (Heinrich's standing privacy rules, applied strictly):** no recognisable real face as the main subject (owners, staff, clients, patients), no child's face at all, no street maps, readable house numbers or private plates, no documents, bank details or chat screenshots; stock and AI model faces in a designed advert are fine; evergreen only (a flyer for a date that has passed is dropped); another brand's or branch's advert is dropped even when it carries the same number. On 2 Nov that left Chantelle (a photographer) and the caregiver without any picture because their flyers show clients and children, and cut 117 pictures by hand or second look (stock brand images, past-dated flyers, another branch's advert); a person can reinstate any of them.
**Find pictures for new businesses:** search Google Maps with the free gosom scraper (`~/.local/google-maps-scraper/…exe -input queries.txt -results places.csv -depth 1 -lang en -exit-on-inactivity 1m`), take the `thumbnail` address and swap its size ending for `=w1600-h1600-k-no`, or take the `og:image` from the business's own site. Look at every picture; crop photos to 4:3 if you like, but keep adverts, flyers and logos whole in their own shape; strip metadata; save at most 1200 wide to the app's `public/media/` with an 800-wide copy `<name>-sm.jpg`; add a line to `data/media-sources.local.json`. Never use a picture that shows residents' houses (the Halloween flyer's street map was cut off for that reason).

## Safe changes: the live site must never go down

Written 2 Nov 2026 after the site showed Railway's "Not Found" page for about 15 minutes. Cause: a storage disk was attached to the service during a Railway builder incident. A service with a disk stops the running copy before the new one starts, the new build then failed on Railway's side (`buildkitd.sock` closed, builds unreliable since the 21 Oct incident), and nothing was left running. Recovery was `deploymentRollback` to the last good deployment, which restarts an old saved image and needs no build.

The rules, and what enforces each:

1. **Only `scripts/hartisboard_deploy.py` changes the live service.** It checks the site is up first (and rolls back before doing anything if it is not), refuses to start while Railway's last two builds both failed (`--force` overrides), remembers the version that is serving, deploys the `live` commit, then requires the real address to answer 200. If the new version does not start and the site is down, it rolls back by itself. `--rollback` does that by hand.
2. **Never publish what does not build.** `npm run ship` runs types, all tests and a production build on the exact commit before it pushes `live`.
3. **Settings that restart the service are not changed casually.** Variables are set with `skipDeploys` and take effect with the next guarded deploy; attaching a disk needs `--yes-restart` and is checked and rolled back like a deploy.
4. **A health check** (`railway.json`, `/manifest.webmanifest`, open even behind the passcode) means a version that cannot answer is never marked healthy.
5. **Deploy outside busy hours.** A service with a disk has a short gap (seconds) on every deploy, because the disk can only be attached to one copy. Moving the counter's and the listings' data to a database would remove that gap.
6. **Recovery by hand, in order:** `python3 scripts/hartisboard_deploy.py --rollback`; if the script cannot run, Railway dashboard, service, Deployments, open the last deployment that ran and choose Rollback. Source -> Branch should be `live` (a redeploy that builds `main` has no real data).

## Visitor counter and the owner's pages

- **Counting:** each phone gets a random code in its own storage the first time it opens the board (no cookie, no name, number, address or IP is saved). `components/Analytics.tsx` sends `visit` (once per visit), `view` (each page once per visit), `install_tap`, `install_ok` (Chrome's install box accepted), `installed` (Chrome's `appinstalled`) and `said_added` ("I already added it") to `/api/hit`, which appends one JSON line to `<storage>/hits.jsonl`. Test browsers (`navigator.webdriver`) and any phone that opened a page with `?skip=1` are not counted (`?skip=0` turns it back on). Code: `lib/analytics.ts` (pure, 9 tests), `lib/analytics-store.ts`, `lib/track.ts`.
- **What the numbers mean:** a visitor is a phone that opened the board in a browser. An iPhone's home-screen icon keeps its own code, so a phone that only ever opened it from the icon is an installer, not a second visitor. "Added to the home screen" = opened from the icon, or Chrome said it was installed. An iPhone cannot report an install, so it counts the first time it is opened from the icon. Two phones in one family are two; clearing browser data counts again. WhatsApp's link preview does not run the board, so it is not a visit.
- **`/stats?key=STATS_KEY`:** visitors today / this week / ever, added to a home screen, using the icon, the visit-to-home-screen funnel, 14 days, iPhone / Android / computer, most-looked-at businesses. Without the key (or without `STATS_KEY` set) the page does not exist. The key is a Railway variable; `python3 scripts/hartisboard_deploy.py --stats-url` prints the address.
- **`/review?key=STATS_KEY`:** everything visitors send waits here and nothing shows on the board until it is approved (below).
- **Storage:** `<storage>` is `STORAGE_DIR`, else the Railway volume (`RAILWAY_VOLUME_MOUNT_PATH`, mounted at `/data`), else `./data`. The stats page warns when the files would be wiped by the next update.

## Listing a business and posting with pictures

- **`/list`** (and "List my business" on Browse and every category page): a service provider adds name, category and kind (plus a free-text "does not fit" note for new categories), areas served, a sentence about the business, a phone / WhatsApp number (a mobile gets a WhatsApp button, a landline is stored as a phone), optional email, website, Instagram, Facebook and hours, and up to 6 pictures (the first is the main picture). **`/post`** (promos) can carry one picture, by default the flyer photo that was just read, and needs the business name. Both need a tick that the pictures are theirs and show no one else's face, child or house number.
- **Nothing goes live by itself.** `POST /api/submit` checks everything (the same validator as the seed, `parseBoard`, so a row the board would drop is an error the person sees), re-draws each picture with `sharp` (turned upright, 1100 px and a 440 px copy as JPEG, so camera data and location are gone; anything that is not a JPG, PNG or WebP is refused), and saves `<storage>/submissions/<id>.json` as `pending` with the pictures in `<storage>/uploads/up-<id>-<n>.jpg`. Limits: 6 sends an hour per address, 14 MB a send, 150 waiting at once. A promo from someone already listed (same number or name) goes under that business; otherwise it also creates one.
- **The owner approves on `/review`:** each card shows the pictures, every field, the word-check flags (health claims, animals or property for sale, which the group does not allow) and a note when it looks like a business already listed. Approve puts the rows on the board (a name taken meanwhile gets a short ending); Reject deletes its pictures. `loadBoard()` reads the approved rows beside the seed; `/media/up-<id>-<n>.jpg` is served from the volume by `app/media/[name]/route.ts` (only names of that exact shape).
- **Homes use the same pipeline** (`/list/home`, see "Houses for sale and rent").
- **Not built yet:** a person editing or removing their own listing later (they message Heinrich), a notice to Heinrich when something is waiting (the count shows on `/stats`), and flyer reading on the live copy (no AI key).

## Feedback: "Tell us" and "Report this post"

- **Where it is:** a blue "Give feedback" button under the install button at the foot of every page (it was a quiet "Something wrong, or an idea? Tell us" line until 3 Nov) (not on `/review` or `/stats`), and "Report this post" on each promo page. Both open the same bottom sheet (`components/FeedbackSheet.tsx`): a choice of "Something is wrong" or "An idea" (a report has no choice), a message of 3 to 1,000 characters, and an optional contact line "only if you want a reply".
- **What goes along by itself:** the page (a path on this site, never an outside address) and the kind of phone (iPhone / Android / computer, opened from the home screen or not, inside Facebook or another app, screen width), built from known words only in `lib/feedback.ts` (`describeDevice`, `cleanPage`). A report also keeps the post's title.
- **Where it is saved:** `<storage>/feedback/<id>.json`, one file per message (`lib/feedback-store.ts`), on the same Railway volume as the submissions. `POST /api/feedback` refuses another site, a body over 4 KB, more than 5 sends an hour per address, a filled hidden box (a robot is told "ok" and nothing is kept), and more than 300 unread messages.
- **How the owner reads it:** on `/review?key=STATS_KEY` under "Feedback" (a Done / Put back button on each), as data at `GET /api/feedback?key=STATS_KEY` (optional `&status=new|done`; this is how Claude reads it), and a count on `/stats`. **Nothing a visitor sends changes the board or the code.** Letting an AI read the list and draft a fix list was chosen over letting it change anything (the research said a person stays in the loop); no AI reads it yet, because the live copy has no AI key.
- **Not built yet:** a notice to Heinrich when a message arrives (the count shows on `/stats`), an AI pass that groups messages and drafts fixes.

## Categories and Sponsored spots (3 Nov 2026)

Research and reasons: `outputs/research/harties-board-categories-and-sponsored-2026-11-03.md`.

- **Categories (`lib/categories.ts`).** Twelve groups: Food & drink, Health & dental, Beauty & wellness, Home & trades (with Solar & backup power and Cleaning & laundry), **Houses for sale & rent (4 Nov, below)**, Property services (estate agents, rentals and letting, bonds and conveyancing; named "Property" until 4 Nov), Kids & learning, Sport & outdoors, Events & markets (with Styling & photography), Cars & transport, Shops, gifts & pets, Business services. The old "More local services" catch-all is gone. `currentCategory()` moves any old `more` pair (seed rows, saved links, listings sent earlier) to its new group, and an old `/c/more` link goes to Browse. Browse hides a group with nobody in it (Property today) until the first listing is approved. The 98 seed rows were moved once by a script (backup of the old file kept in the session scratchpad); `scripts/harties_seed.py` in the workspace still writes the old groups, and the legacy mapping covers that, but give it the new ids before the next re-read.
- **Health wording flags (`healthFlags` in `lib/moderation.ts`).** Every orthodontist listing is flagged on `/review` ("check the HPCSA register shows them as a registered specialist"), and a health listing with "best", "cheapest", "specialist" or a discount in it is flagged. Flags only: nothing is rejected.
- **Sponsored spots (`lib/sponsor.ts` holds every number).** `sponsored: true` (and an optional `sponsoredUntil`, the last paid day) on a business, or on one promo, in the seed. A sponsored business gets: 2 spots at the top of its category page (sub-group chips respect the kind), 1 at the top of a search it matches, and its promo first on a Today, This weekend or This week list (one per list, on the first day that has one). The card is the normal card with a gold edge and a gold "Sponsored" pill pinned to the picture (the South African ad code and the FTC both ask for a plain label above the title; the old word "Featured" is in neither list). Sponsors take turns by the same date-seeded shuffle, and a sponsored place is not repeated in the A to Z list. Health listings are on hold (`PAID_HOLD`) until an HPCSA or lawyer opinion says paid prominence is allowed. Nothing is sponsored on the live site; to switch one on, edit the seed, `npm run ship`, then the guarded deploy.
- **`/promote` ("Be seen first").** The third tab of the Post page (labelled "Sponsored"): where a spot shows, a made-up card that cannot be tapped (`inert`), and "Get a Sponsored spot", which asks for a number or email and reaches `/review` as "Wants a Sponsored spot" (a fourth feedback kind). No price is shown.
- **Feedback button.** The foot of every page holds a solid blue "Give feedback" button (52px tall, white on blue 5.7:1), the only blue on the board. The install line at the foot is hidden while the black install bar is showing.
- **Small words removed:** the "For the owner, in the pilot" box on business pages, "Coming next", the per-tile week count on Browse, the area note under the area switch, the "running now" note, the Saved intro and its second install card, and most intro text on Post and List.

## Houses for sale and rent (4 Nov 2026)

Heinrich (3 Nov, then 4 Nov): the Property24 and PrivateProperty listings the scrape found should be in the app with their photos, "added to the categories, a different type of category as houses", **not a tab of its own**. So Houses is a normal category on Browse (red house icon, `data-cat="houses"`), with three kinds: **For sale**, **Stands & land**, **To rent**.

- **A home is a Business with an extra `home` field** (`HomeFacts` in `lib/types.ts`), so search, saving, areas, the page route `/b/<slug>` and the photo handling all work unchanged. The facts: deal, kind (house, townhouse, apartment, stand), estate, price (the rent is a month), bedrooms, bathrooms, parking, stand and floor size, levies and rates when known, **agency and agent** as the portal names them (with a link to their portal page), one or two links to the **original listing**, the day it was read (`seenOn`) and an `order` number for "newest". `parseHome` in `lib/parse-board.ts` drops a home that has no deal, kind, place, day or portal link, and drops a wrong figure without dropping the home. Only `https` links on property24.com or privateproperty.co.za are accepted, and the portal's name is taken from the link itself (`lib/homes.ts`).
- **What a card and a page say** (`HomeCard`, `HomeDetails`, `HomesView`): the price first, then what and where, then rooms, then who is selling it and a line saying which site it is on ("On Property24"); the day it was last looked at, "Last checked 3 Nov", is on the home's own page; the main button goes to the original listing ("Listing" on a card, "Full listing on Property24" on the page, "Also on PrivateProperty" when the same home is on both). The page says prices and availability change, and has "Sold or wrong? Tell us" (the existing report sheet; the page address goes along). **Facts only: the portals' marketing text, the street address and the map position are never kept** (the app's rule: areas, never addresses).
- **The Houses page has three searches, Buy, Rent and Land, and land is never mixed into the others** (4 Nov: Heinrich saw stands among the houses in Broederstroom). It opens on Buy. Which search a home belongs to is decided from its own facts (`segmentOf` in `lib/home-search.ts`: a stand is Land, a rental is Rent, the rest is Buy), not from the seed's subcategory, so a mislabelled stand still cannot appear in Buy. It shows 24 homes at a time ("Show more homes", up to 480, unchanged). "Newest" is each listing's place within its own portal and deal (the portals count differently and PrivateProperty numbers rentals apart from sales).
  - **The filters** (modelled on Property24, RE/MAX, Pam Golding and Rightmove; the research is in the history row): **Where** (the estates and suburbs of the area chosen for the whole app, each with its count, grouped by area under All of Harties), **Type** (house, townhouse, apartment), **Beds**, **Baths**, **Parking** (each "N or more"), **Min and Max price** (the rent a month on Rent), **Stand size** min and max (in More filters on Buy and Rent, on the page for Land), **Agency**, a words box (agent, agency or estate), and **Order**: Newest, Price: low to high, Price: high to low, Biggest stand, Most bedrooms, and on Land Lowest R per m2. Everything is in the address (`lib/home-query.ts`: `sub`, `type`, `beds`, `baths`, `park`, `min`, `max`, `smin`, `smax`, `at`, `by`, `q`, `sort`, `n`), so a link can be shared, and a broken or hand-edited address falls back to "not chosen" instead of breaking the page.
  - **Location-specific:** the Where list, the price steps and the stand-size steps follow the homes actually in the place (Broederstroom stops at a few million, Pecanwood goes past thirty); the steps are in `lib/home-ladders.ts`. Estate names are one name per estate whatever the portal calls it ("Pecanwood" and "Pecanwood Estate", "The Island Estates" and "The Islands Estates"; `ESTATE_ALIASES` in `harties_homes.py`).
  - **Every number on a choice is the number of homes tapping it shows** (a choice is counted with all the other filters applied; `homeChoices`), a choice that would show nothing is left out of a list or greyed out, and chosen filters show as buttons that take each off, with Clear all. A search that finds nothing says what taking each filter off would give ("Without 5+ bedrooms: 6 homes for sale"). A filter on a figure the listing did not give leaves that home out (a price range hides "price on the listing"). Land ignores the room and kind filters.
